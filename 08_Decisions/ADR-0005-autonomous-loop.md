# ADR-0005 — 無人LOOP基盤（自動再開・並行安全・暴走防止）の設計

- 状態: 設計確定（2026-07-03）／**実装は後続タスクで人間承認後**
- 決定者: 人間（オーナー）＋ Knowledge Doer（設計）
- 関連: ADR-0001（無クラウド）・ADR-0002（自律ガードレール）・ADR-0003（可逆性）・ADR-0004（再開性）

---

## 1. 目的

利用制限（5時間ごと等）・コンテキストクリア・並行セッションがあっても、**ファイルを壊さず・暴走させず・人間を張り付かせずに**、AI LOOP が自動で「続き」を拾って進む基盤を設計する。本ドキュメントは**設計の確定**であり、実装（スクリプト・スケジューラ登録・動作検証）は後続タスクで行う。

## 2. 確定した方針（人間承認済み）

| 論点 | 決定 |
|------|------|
| **自律範囲** | タスク frontmatter に `auto: true` が付いたものだけ無人着手可。印の無い `todo` には手を出さない。`doing`/`checking` の継続は常に可。 |
| **起動間隔** | 30分ごと（アイドル時は即終了するため空振りは軽量） |
| **コスト歯止め** | 1日の自動実行回数・1回あたり実行時間に上限＋停止スイッチファイルで即全停止 |

**どの案でも絶対にやらないこと（不変）**：T2タスクの実行／`approval → done`（人間専用・§4.1）／§12ゲートの開放／保護ブランチへのpush・外部送信・削除。

## 3. 全体構成

```
Windows タスクスケジューラ（30分ごと・「実行中なら新規起動しない」）
      │  起動
      ▼
ランチャースクリプト（tools/loop_tick.* ・実装は後続）
   1. 停止スイッチ確認     .claude/loop.disabled があれば即終了
   2. コスト歯止め確認     当日の実行回数/時間が上限なら終了
   3. ロック取得（PID方式） 他プロセスが生存中なら終了（単一書き手保証）
   4. 作業ツリー確認       git 未コミット変更があれば defer（他セッション作業中）
   5. 着手対象の有無を判定  doing/checking、または auto:true の todo が無ければ終了
   6. claude をヘッドレス起動（固定の再開プロンプト・実行時間上限つき）
   7. 記録＆ロック解放      loop ログ追記・状態更新・ロック削除（異常時も必ず解放）
```

## 4. 単一書き手の保証（並行安全）

`SPEC §4.1`（status の書き手は1つ）を運用レベルで守るための多層防御。

### 4.1 PIDベースのロック（時間ではなくプロセス生死で判定）
- `.claude/loop.lock` に **PID・開始時刻・ホスト/セッション識別**を記録。
- 起動時：ロックがあり、その **PID がまだ生存**していれば → 別の実行が動作中とみなし**何もせず終了**。
- ロックが無い、または **PID が既に終了している**（前回が正常終了でも異常終了でも）→ 安全なので自分のPIDで取得し直して続行。
- 「アプリを正しく閉じたか」を人間が気にする必要がない（生死をOSが正確に教える）。

### 4.2 dirty-tree defer（対・人間/他セッション）
- ロックは「LOOP同士」の衝突を完全に防ぐが、**人間の対話セッションはロックを取らない**ため衝突余地が残る。
- そこで、着手前に `git status` を確認し、**未コミットの変更があれば今回は見送る**。人間や他セッションが編集中＝未コミット変更あり、という関係を利用して、活動中のセッションを踏まない。

### 4.3 残留リスクと対処（正直な記載）
- 「作業ツリーがクリーンな瞬間」に人間が対話を始めた直後、LOOPが起動すると理論上は重なりうる。
- 対処：(a) LOOP実行は**1タスク進めたらコミットして即終了**の短命設計にして窓を狭める、(b) ADR-0003の**各ステップ・コミット単位の退避**で、万一重なってもGit復元点まで戻せる、(c) 対話で集中作業する間は `.claude/loop.disabled` を置けばLOOPは完全に黙る。

## 5. 3つのケースの挙動（要件充足の確認）

### 5.1 5時間制限に掛かった場合
- 制限中に発火した tick は、手順6の `claude` 起動が失敗する → ランチャーが捕捉し「limit-hit」を記録し**ロックを解放して終了**（ここが要：失敗時も必ず解放）。
- 30分後の次の tick が再挑戦。**制限が解けた最初の tick で自然に成功**する。人間の操作は不要。

### 5.2 コンテキストクリア／auto-compact
- tick ごとの `claude` 起動は**会話文脈を持たない前提**。だからクリアは問題にならない。
- 状態はすべてファイル（`PROGRESS.md`・タスクのメモ・`10_Runs/`）にあり、ADR-0004の再開プロトコルで**ファイルから続きを復元**する。

### 5.3 並行セッション
- LOOP同士：PIDロックで排他（4.1）。
- LOOP対人間：dirty-tree defer ＋ 短命実行 ＋ ステップコミットで実務上回避（4.2・4.3）。

## 6. 無人時の自律範囲（何を進め、何を止めるか）

起動した LOOP が1回で行う判断：

1. `status: doing` / `checking` のタスクがあれば、その**続き**を ADR-0004 のステップリストから再開して1歩進める。
2. 無ければ、`status: todo` かつ `auto: true` かつ `tier: T0/T1` のタスクを**1件**着手する。
3. どちらも無ければ即終了（busywork をしない）。
4. 進めた結果が `checking` 完了なら `approval` まで status を動かして**停止**（`done` は人間）。
5. 以下に当たったら進めず記録して停止：T2到達／`approval`到達／§12ゲート必要／`max_cost_usd`・`max_attempts` 超過／要件が本質的に不明。

## 7. 暴走・浪費の防止（コスト歯止め）

- `.claude/loop_state.json` に当日の**実行回数・累計時間・（取得可能なら）概算コスト**を記録。
- 上限（初期値の目安・調整可）：**1日あたり自動実行 ≤ 20回**、**1回 ≤ 10分**。超過したらその日は自動起動をスキップ。
- 各タスクの `max_cost_usd` / `max_attempts` を厳守。`max_attempts` 超過タスクは触らず `blocked` 相当で人間へ。
- **停止スイッチ**：`.claude/loop.disabled`（空ファイルでよい）があれば、tick は即終了。人間の即時オフ手段。

## 8. 観測（静かに壊れないための可視化・SPEC §8）

- 毎 tick、`10_Runs/_loop/YYYY-MM-DD.jsonl` に1行追記：`{ts, outcome, task_id?, note}`。
  - outcome の例：`disabled` / `busy` / `dirty-defer` / `idle` / `worked` / `limit-hit` / `budget-reached` / `error`。
- これにより「LOOPが生きているか」「何をしたか／なぜ何もしなかったか」を人間が後から追える。
- HOME.md に「直近のLOOP稼働状況」を出す（実装時に検討）。

## 9. 本設計で"作らない"もの（ADR-0001整合）

- **クラウド上の定期実行（スケジュール済みルーティン）は使わない**。起動は Windows タスクスケジューラ＝ローカルOS機能のみ。これは「自動化 ≠ クラウド」（ADR-0001）に合致。
- 常駐デーモンは作らない（tick 型で十分・状態はファイル）。

## 10. 実装スコープ（後続タスク・要人間承認）

本ADRは設計確定まで。実装は別タスクとし、**着手には人間の承認が必要**（新しい自動起動の仕組み＝スコープ拡大・トークン消費を伴うため／ADR-0002）。実装物：

1. ランチャースクリプト（PIDロック・dirty-tree判定・停止スイッチ・状態更新・ロック確実解放）
2. 固定の再開プロンプト（§6の判断規則を埋め込む）
3. Windows タスクスケジューラ登録（30分・「実行中なら新規起動しない」）
4. 段階導入：まず**手動で tick を数回叩いて挙動確認** → 問題なければスケジューラ有効化
5. `auto:` フィールドを `02_Tasks/TASK-template.md` に追記（既定は付けない＝false）

## 11. 帰結

- 5時間制限・クリア・並行のいずれでも、**人間が張り付かずに、壊さず・暴走せず**に自動再開する道筋が設計として確定した。
- 制限そのもの（Anthropic側の枠）は回避できない。本設計が保証するのは「解けた瞬間を人間が覚えていなくても自動で掴む」ことと「掴む際に壊さない」こと。
- 次の区切り：この設計の**承認**。その後、別タスクで実装に着手する。
