# ADR-0004 — セッション中断（利用制限・コンテキストクリア）からの再開性を保証する

- 状態: 承認（2026-07-03）
- 決定者: 人間（オーナー）

---

## 背景

Claude Code には利用量の制限（5時間ごとのリセット等）があり、長時間・多段の作業の途中でセッションが打ち切られることがある。また、コンテキストウィンドウの都合で `/clear` や新規セッション開始が必要になることもある。

このシステムは元々「会話の記憶ではなくファイルを正本にする」設計（SPEC §3.6・CLAUDE.md）だが、**長時間の作業中に、どこまで進んだかを本文（タスクのメモ・実行ログ）に十分な粒度で書き残していないと、直近のコミット以降の作業が再現できず、やり直しのコストが発生する**。

## 決定

**中断は前提として起きるものとして扱い、「直近のコミット／メモ更新」以降しか失われないように、チェックポイントの粒度を上げる。**

### 1. 正本はファイル（既存原則の再確認）
タスクの `status`・メモ、`10_Runs/` の実行ログ、`PROGRESS.md` の現在地——この3つを読めば「どこまで進んだか」が会話なしで完全に再構成できる状態を常に保つ。

### 2. 長時間・多段の作業は着手時にステップを書き出す
見積もりで複数ステップにまたがる作業（例：多数のファイル生成、複数回のビルド、長い分析）に着手する前に、タスクファイルの「メモ」に**簡単なステップリスト**を書く。各ステップが終わるごとにチェックを付けて更新する。

```
## 進行状況（中断時の再開用）
- [x] 1. データ読み込み・整合性チェック
- [x] 2. 集計・グラフ生成
- [ ] 3. PPTX組み立て ← ここで中断した場合はここから
- [ ] 4. レイアウト自動検査
- [ ] 5. Checker検証
```

### 3. コミットの粒度（ADR-0003の運用を強化）
ADR-0003の「着手時と各まとまりでコミット」を、**長時間タスクではより細かい単位**で実践する。1つの大きな成果物が完成するまで無コミットで抱え込まない。

### 4. セッション開始時のプロトコル
新しいセッション（中断からの再開・全く新規、いずれも）では、**新しい依頼に着手する前に**、以下を確認する：
- `PROGRESS.md` の「現在地」
- `status: doing` または `checking` のタスクの有無（HOME.md／`grep status: doing`）

該当タスクがあれば、その「メモ」のステップリストと直近の `10_Runs/` ログを見て、**そこから再開する**。人間から別の指示があればそちらを優先するが、デフォルトの挙動としてはこの確認を行う。

## 帰結

- `CLAUDE.md` に §9 として要約を常時文脈化。
- `05_Agents/build-doer.md`・`knowledge-doer.md` に、長時間作業時のチェックポイント記録を明記。
- 人間側の対応：中断に気づいたら、特別な操作は不要。次のセッションで話しかければ、上記プロトコルに従って自動的に状況確認から始まる。気になる場合は「続きから再開して」と伝えるとより確実。

## 効果

- 中断で失われる作業は「直近のステップ更新／コミット以降」だけに限定される。
- `max_cost_usd`／`max_attempts` の消費も、ゼロからのやり直しを避けられる分、無駄になりにくい。
