# ADR-0001 — AI LOOP はクラウドを使わずローカル完結とする

- 状態: 承認（2026-07-02）
- 決定者: 人間（オーナー）

---

## 背景

SPEC.md は実行系を2つ想定している（§3.7）：ローカル実行系と、クラウド Routines 系。
クラウド Routines はフェーズ3で「Routines/スケジューラ導入」（§10）として、また §11 末尾に「使う場合の1本」として言及されている。

一方で本プロジェクトの方針として、**AI LOOP 本体は最終フェーズに至ってもクラウドを利用しない**ことがオーナーより明示された。

## 選択肢

1. SPEC どおりフェーズ3でクラウド Routines を導入する。
2. **クラウドは一切採用せず、必要な自動化はローカルで実現する。**（採用）

## 決定

**選択肢2を採用する。** AI LOOP 本体はローカル（Claude Code Desktop/CLI ＋ ローカルファイル＋Git）で完結させ、クラウド Routines は採用しない。

- この決定は SPEC.md のクラウド関連記述（§3.7、§11 末尾の任意 Routine、§10 フェーズ3の「Routines/スケジューラ導入」）に優先する。
- 優先順位（`07_Policies/priority-order.md`）上、これは「プロジェクト要件」に相当し、SPEC の一般記述より上位に立つ。

## 帰結

- クラウド Routine（cron クラウドエージェント、scheduled-tasks 等）を登録・提案しない。
- **自動化 ≠ クラウド**。将来タスク整理・リンク検査・ブリーフ生成などを自動化する場合も、**ローカルのスケジューラ／手動実行**で実現する。
- `README.md` のクラウド Routines 文言は「不採用」と明記する（本 ADR とあわせて実施）。
- SPEC.md 本体は正典として据え置き、読み替えは本 ADR を根拠とする。
- 既存の不変条件（§4.1 の追記専用ルール等）は、そもそもローカルのみでも矛盾なく成立する。

## 補足

「クラウドを使わない」は「自動化しない」を意味しない。信頼勾配（T0〜T2）と人間承認の設計は本決定と独立に維持される。
