# 概要
`00_Inbox/00_attachment_files/20260803/AI_LOOP_要件定義書_v1−1.docx` に基づき、Webサイト（Phase1）を対象に「デザイン生成→実装生成（HTML/CSS/JS）→検証（Lint・アクセシビリティ・レスポンシブ・ビジュアル差分・支給素材非改変）→修正」を反復するAI LOOPシステムを新規開発する。既存の `PROJECT-001-watashiwa-lulu`（ロゴ・HTML・WordPressテンプレート制作）で実地に回した手順を、再利用可能なソフトウェアとして一般化するもの。詳細な意思決定根拠は [[ADR-0007-ai-loop-engine-build]] を参照。

# 目的
- Webサイト案件について、要件受付〜デザイン案生成〜実装生成〜自動検証〜収束判定〜人間承認までを1つのCLIで実行できるようにする
- 支給素材（ロゴ・メインビジュアル・挿入画像・バナー等）を固定要素として登録し、意匠を改変せずデザイン・実装へ組み込む機能を持たせる
- ロゴ／イラスト／バナー／CMSアダプタ等、将来フェーズをコア改修なしに追加できる拡張点（テンプレート・出力アダプタ・CMSアダプタのレジストリ）を用意する

# スコープ / 制約
- やること：要件定義書 5.1〜5.5・5.7（Webサイト向け）のMust/Should項目に対応する実働ソフトウェアを `ai-loop-engine/` に構築する。テンプレート／出力形式／CMSアダプタの拡張点（レジストリ）も用意する。
- やらないこと：ロゴ／イラスト／バナーの生成テンプレート中身の実装、WordPress以外のCMSアダプタ、CMSへのライブ投入（F-304）、認証情報の暗号化保管（NF-302）、商標類似度チェック（NF-303）、コスト計測・上限アラート（NF-403）。いずれもPhase2以降・実測ドリブンで着手する。
- 制約：本システムの内部データストアはSQLiteを使わずファイルベースJSON（版は追記、上書きしない）とする。人間参加のチェックポイント（デザイン案選定・最終承認）は自動化しない。外部送信・本番CMSへの投入・認証情報の変更は行わない。Vault自身の運用管理（02_Tasksのstatus管理等）には手を加えない。
