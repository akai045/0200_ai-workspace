# 01_Projects — プロジェクト文脈

## 用途

複数タスクにまたがる「プロジェクト単位の文脈」を置く。

- プロジェクトの背景・目的・制約・関係者
- そのプロジェクトに属するタスクが参照する共通前提
- タスクの frontmatter の `project:` から参照される

## ルール

- 1プロジェクト＝1ファイル（または1サブフォルダ）。`PROJECT-001.md` のように採番する。新規作成は `PROJECT-template.md` をコピーする（既存の最大連番+1）。
- プロジェクト要件は優先順位（`07_Policies/priority-order.md`）で「3. プロジェクト要件」に相当する。個別タスク指示より上位。
- 中身（概要・目的・スコープ）は人間が会話で伝えた内容から下書きしてよい。人間が確認・修正する（タスクの intake と同じ分担）。
- このテンプレートには実プロジェクトは含まれていません（`PROJECT-template.md` のみ）。最初のプロジェクトはあなたの最初の依頼から作られます。

## タスク作成時の project 紐づけ判断ルール

タスクの `project:` は今のところ**作成者（人間 or Claude）が手で書く**。自動マッチングは無い。曖昧なときの判断は次の順で行う。

1. **既存プロジェクトと明確に一致** → その `project_id` を設定する。
2. **一致するプロジェクトが無いが、同テーマ（タイトルの頭語・キーワードが重複）で `project:""` のタスクが既に2件以上ある、または今回の追加で2件以上になる** → **プロジェクト化してよいか人間に一度だけ確認する**。
   - 承認された → `PROJECT-template.md` から新規登録し、該当タスク群の `project:` を書き換えて紐づけ、新規プロジェクトファイルの「関連タスク」にも追記する。
   - 見送られた → 下表「プロジェクト化を見送ったテーマ」に1行追記し、**以後そのテーマについては自動で再提案しない**。人間から明示的に依頼があれば、その時点でいつでも対応する（依頼駆動なら過去の見送りに関係なく実行する）。
3. **既存にも一致せず、テーマの重複も無い一回きりの依頼** → `project:""` のままにする（不確かな紐づけで優先順位§4.3「3.プロジェクト要件」を汚さない。source-verificationの「不確かなら断定しない」と同じ考え方）。
