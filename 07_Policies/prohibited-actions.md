# prohibited-actions — 共通禁止事項

> 全エージェント・全タスクに適用される禁止事項。個別タスク指示より上位（`priority-order.md`）。

---

## 全体共通の禁止

- **人間承認なしの不可逆・外部操作**（外部送信、本番反映、削除、顧客データ変更、権限変更、課金、セキュリティ設定変更）。これらは T2 であり、必ず人間承認を経る。
- **可変状態（status）の無断書き換え**。status を動かせる主体はルールで固定（下記）。
- **根拠なき断定**。出典・根拠のない記述をしない（「根拠なし記述率」は監視指標）。
- **要件・受入条件の無断変更／自分で緩める行為**。
- **推測で確定事項を上書きする行為**（優先順位の最下位、`priority-order.md`）。
- **認証情報・秘密情報のハードコードや外部漏洩**。
- **復元点なしのデータ変更**。破壊的か否かを判定して退避を決めない（判定ミスで静かにすり抜ける）。**全変更を1経路に通し無条件に退避**する default-safe を既定とする（ADR-0003）。ユーザーデータを復元不能な形で消さない。

---

## status の書き手（SPEC §4.1）

- status を書き換えられるのは **ローカルの人間 / Claude Code だけ**。
- Doer が動かせるのは `doing → checking` まで。
- `checking → approval` は Checker、`approval → done` は人間のみ。
- **クラウド Routines は status を一切書き換えない（追記専用）**。レポートは `10_Runs/` に新規ファイルで出すだけ。

---

## Knowledge Doer の禁止

- Bash 実行、アプリコード変更、パッケージ追加、外部送信、削除。
- 指定された成果物フォルダ以外への書き込み。

## Build Doer の禁止

- 本番ブランチ（保護ブランチ）への直接反映・push。
- 外部送信、本番データ変更、認証情報の変更。
- 人間承認なしの削除・破壊的操作。

## Checker / Auditor の禁止

- 成果物の大きな改変（Checker は差し戻すだけ）。
- 自分が作った素材を自分で検査すること（独立性の毀損）。

---

## クラウド Routines の禁止（SPEC §3.7・§4.1）

- 本番操作、ローカル Obsidian 処理、SQLite 依存処理、**T2 タスク**。
- タスクの status 書き換え。保護ブランチへの push（既定では `claude/*` のみ）。
- **T2 タスクの Routines 自律実行は恒久的に禁止**（承認プロンプトがないため）。
